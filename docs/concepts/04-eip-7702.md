# EIP-7702 Delegation

[EIP-7702](https://eips.ethereum.org/EIPS/eip-7702) lets an EOA delegate its code to a contract. The EOA keeps its address and gains smart account capabilities (batching, sponsorship, modules) without deploying a separate contract.

## How It Works

1. The EOA signs an authorization that designates a smart account implementation.
2. The UserOperation that delegates the EOA carries that authorization; once it lands, the EOA's code points to the implementation.
3. The EOA address stays the same and no factory is involved.

## Supported Accounts

| Account | Constructor | Delegate | EntryPoint |
|---------|-------------|----------|------------|
| [Simple](../accounts/simple-smart-account.md#eip-7702-mode) | `SimpleSmartAccount.from({ ..., eip7702: true })` | SimpleAccount implementation (`implementation`) | 0.8 (default) or 0.9 |
| [Kernel](../accounts/kernel-smart-account.md#eip-7702) | `KernelSmartAccount.from({ ..., eip7702: true })` | Kernel 0.3.3 (`implementation`) | 0.7 |

## Usage

```typescript
import { Account, Actions, Client, http } from "viem"
import { sepolia } from "viem/chains"
import { SimpleSmartAccount, SmartAccountClient } from "permissionless"

const owner = Account.fromPrivateKey("0x...")
const publicClient = Client.create({ chain: sepolia, transport: http() })

const account = await SimpleSmartAccount.from({
    client: publicClient,
    owner,
    eip7702: true
})

account.address === owner.address // true

const smartAccountClient = SmartAccountClient.create({
    account,
    chain: sepolia,
    bundlerTransport: http("https://bundler.example.com")
})

// Sign the delegation yourself and attach it to the UserOperation that delegates the EOA.
const authorization = await owner.signAuthorization({
    address: account.authorization.address,
    chainId: sepolia.id,
    nonce: BigInt(
        await Actions.address.getTransactionCount(publicClient, {
            address: owner.address
        })
    )
})

const hash = await smartAccountClient.sendTransaction({
    to: "0x...",
    value: 0n,
    data: "0x",
    authorization
})
```

Later UserOperations omit `authorization`. Kernel signatures made before delegation verify once the EOA has code.

## Key Differences from Standard Accounts

| Aspect | Standard account | EIP-7702 account |
|--------|------------------|------------------|
| Address | Counterfactual, derived from the factory | The owner EOA |
| Deployment | Factory deploys on the first UserOperation | None; the authorization delegates the EOA |
| `getFactoryArgs()` | `{ factory, factoryData }` until deployed | `{ factory: undefined, factoryData: undefined }` |
| `factoryAddress`, `index`, `address` | Available | Not available (typed `undefined`) |
| `nonceKey` | Available | Available |
| `account.authorization` | -- | `{ account: owner, address: delegate }` |

## Parameters

In EIP-7702 mode `SimpleSmartAccount.Parameters<entryPointVersion, true>` is:

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `client` | `Client.Client` | Yes | -- | viem client for on-chain reads |
| `owner` | `Account.Local \| WalletClient \| EthereumProvider` | Yes | -- | The EOA to delegate |
| `entryPoint` | `"0.8" \| "0.9" \| { address, version }` | No | `"0.8"` | EntryPoint |
| `implementation` | `Address` | No | `0xe6Cae83BdE06E4c305530e199D7217f42808555B` on 0.8, `0xa46cc63eBF4Bd77888AA327837d20b23A63a56B5` on 0.9 | Delegate contract |
| `nonceKey` | `bigint` | No | `0n` | Nonce key used when a call passes none |

Kernel takes its regular parameters minus the factory ones; see [KernelSmartAccount](../accounts/kernel-smart-account.md).

## Internals

With `eip7702: true` the account is built on viem's `SmartAccount.from` with `authorization: { account: owner, address: implementation }`, `getAddress` returning the owner address and empty factory args. Simple signs UserOperations as EIP-712 typed data on 0.8 and 0.9; Kernel signs with its EIP-7702 root validator.
